# 2.6. Thiết kế ứng dụng client

Ứng dụng client **VinaPharma App** là ứng dụng web một trang (SPA). Ứng dụng chạy trên trình duyệt và chỉ giao tiếp với máy chủ qua REST API `/api/v1` (mục 2.5). Client không dùng session hay cookie của máy chủ.

- **Công nghệ:** HTML, Bootstrap 5, JavaScript thuần (Fetch API), không cần bước build. Mã nguồn ở `src/main/resources/static/app/` (`index.html`, `app.js`, `app.css`), truy cập tại `http://<máy chủ>/app/`.
- **Định tuyến phía client:** theo hash URL (`#/products`, `#/cart`...). Mỗi route ứng với một hàm vẽ màn hình.
- **Trạng thái phía client:** lưu trong `localStorage` của trình duyệt:
  - access token và thông tin người dùng;
  - giỏ hàng;
  - mã giảm giá đang nhập.
- **Lớp gọi API dùng chung:** hàm `api(method, path, body)`. Hàm này:
  - gắn header `Authorization: Bearer <token>`;
  - gửi JSON, hoặc `FormData` khi có tệp;
  - bật / tắt thanh loading;
  - chuẩn hóa mọi lỗi thành đối tượng `ApiError {status, message, errors}`.

## 2.6.1. Thiết kế giao diện

**Danh sách màn hình chính**

| STT | Màn hình | Route | Đối tượng | Mô tả |
|---|---|---|---|---|
| 1 | Danh sách sản phẩm | `#/` | Tất cả | Ô tìm kiếm, lọc danh mục, sắp xếp, lưới thẻ sản phẩm (ảnh, loại thuốc, giá, tình trạng còn hàng), phân trang |
| 2 | Chi tiết sản phẩm | `#/products/{slug}` | Tất cả | Thông tin thuốc (hoạt chất, dạng bào chế, số đăng ký...), chọn đơn vị và số lượng, thêm vào giỏ, công dụng / cách dùng, đánh giá, thuốc tương đương |
| 3 | Đăng nhập / Đăng ký | `#/login`, `#/register` | Khách vãng lai | Form đăng nhập bằng email hoặc số điện thoại; form đăng ký |
| 4 | Giỏ hàng | `#/cart` | Khách hàng | Danh sách dòng hàng, sửa số lượng (0 = xóa), nhập mã giảm giá, dùng điểm, tổng tiền do server tính |
| 5 | Đặt hàng | `#/checkout` | Khách hàng | Chọn hình thức nhận, chọn từ sổ địa chỉ hoặc nhập địa chỉ, chọn phương thức thanh toán, tải ảnh đơn thuốc nếu có thuốc kê đơn |
| 6 | Đơn hàng của tôi | `#/orders` | Khách hàng | Danh sách đơn: mã, trạng thái, ngày đặt, tổng tiền |
| 7 | Chi tiết đơn hàng | `#/orders/{code}` | Khách hàng | Sản phẩm, tiền, người nhận, lịch sử xử lý; nút hủy đơn, thanh toán online, mã QR chuyển khoản |
| 8 | Tài khoản | `#/account` | Đã đăng nhập | Sửa hồ sơ, sổ địa chỉ (thêm / xóa) |
| 9 | Tư vấn | `#/consult` | Khách hàng | Khung chat với trợ lý AI / dược sĩ, nút "Gặp dược sĩ" |
| 10 | Nghiệp vụ nhà thuốc | `#/staff` | Dược sĩ, quản trị | Số liệu công việc, đơn thuốc chờ duyệt (từ chối), đơn chờ xác nhận (xác nhận) |
| 11 | Quản lý sản phẩm | `#/admin/products` | Quản trị | Bảng sản phẩm, tìm kiếm, nút thêm / sửa / xóa |
| 12 | Thêm / sửa sản phẩm | `#/admin/products/{id\|new}` | Quản trị | Form thông tin, giá, đơn vị quy đổi, trạng thái kinh doanh |

**Bố cục chung:**
- thanh điều hướng trên cùng: logo, menu theo vai trò, số lượng trong giỏ, tên người dùng / đăng xuất;
- thanh tiến trình mỏng báo đang tải;
- vùng nội dung;
- thông báo nổi (toast) ở góc dưới phải.

Menu thay đổi theo vai trò trong token: khách hàng thấy Giỏ hàng, Đơn hàng, Tư vấn; dược sĩ thấy Nghiệp vụ; quản trị thấy thêm Quản lý sản phẩm. Giao diện co giãn theo màn hình điện thoại (lưới Bootstrap).

## 2.6.2. Thiết kế tích hợp API

| Chức năng client | API sử dụng | Method |
|---|---|---|
| Hiển thị danh sách, tìm kiếm, lọc sản phẩm | `/api/v1/products`, `/api/v1/categories` | GET |
| Xem chi tiết sản phẩm, đánh giá | `/api/v1/products/{slug}`, `/api/v1/products/{slug}/reviews` | GET |
| Đăng nhập | `/api/v1/auth/login` | POST |
| Đăng ký | `/api/v1/auth/register` | POST |
| Đăng xuất | `/api/v1/auth/logout` | POST |
| Tính tiền giỏ hàng (mỗi lần sửa giỏ, nhập voucher) | `/api/v1/cart/quote` | POST |
| Nạp dữ liệu màn hình đặt hàng | `/api/v1/store`, `/api/v1/me/addresses`, `/api/v1/me`, `/api/v1/cart/quote` | GET, GET, GET, POST |
| Đặt hàng (kèm ảnh đơn thuốc nếu có) | `/api/v1/orders` | POST |
| Thanh toán online | `/api/v1/orders/{code}/payment` | POST |
| Xem danh sách / chi tiết đơn hàng | `/api/v1/orders`, `/api/v1/orders/{code}` | GET |
| Hủy đơn hàng | `/api/v1/orders/{code}/cancel` | POST |
| Xem / sửa hồ sơ | `/api/v1/auth/me`, `/api/v1/me` | GET, PUT |
| Thêm / xóa địa chỉ | `/api/v1/me/addresses`, `/api/v1/me/addresses/{id}` | POST, DELETE |
| Chat tư vấn (lấy tin mới mỗi 3 giây / gửi tin) | `/api/v1/consult/messages` | GET, POST |
| Chuyển sang dược sĩ | `/api/v1/consult/handoff` | POST |
| Bảng công việc nhân viên | `/api/v1/staff/dashboard`, `/api/v1/staff/prescriptions`, `/api/v1/staff/orders?status=PENDING` | GET |
| Từ chối đơn thuốc | `/api/v1/staff/prescriptions/{id}/reject` | POST |
| Xác nhận đơn hàng | `/api/v1/staff/orders/{id}/status` | POST |
| Hiển thị danh sách sản phẩm (quản trị) | `/api/v1/admin/products` | GET |
| Thêm sản phẩm | `/api/v1/admin/products` | POST |
| Cập nhật sản phẩm | `/api/v1/admin/products/{id}` | PUT |
| Xóa sản phẩm | `/api/v1/admin/products/{id}` | DELETE |

**Luồng dữ liệu từ giao diện đến API** (ví dụ đặt hàng):

1. Người dùng điền form Đặt hàng và bấm "Xác nhận đặt hàng".
2. Client đọc dữ liệu form và ghép với giỏ hàng trong `localStorage` thành body JSON. Nếu có thuốc kê đơn, client dựng `FormData` gồm `items[i][...]` và tệp `prescription`.
3. Hàm `api('POST', '/orders', body)` gắn Bearer token, bật thanh loading, khóa nút gửi và gọi `fetch`.
4. Máy chủ xử lý theo luồng: Spring Security (kiểm tra token, vai trò) → `ShoppingApi` → `OrderService` (kiểm tra tồn kho, khuyến mãi, ghi đơn) → JPA / MySQL. Kết quả trả về JSON theo định dạng chuẩn.
5. Client nhận kết quả:
   - **201:** xóa giỏ hàng, hiện thông báo thành công, rồi theo `nextAction` mở cổng thanh toán hoặc chuyển tới `#/orders/{code}`;
   - **lỗi:** hiển thị lỗi ngay trên form, giữ nguyên dữ liệu đã nhập.

**Xử lý trạng thái loading, thành công và lỗi**

| Trạng thái | Cách xử lý trên client |
|---|---|
| Đang tải | Thanh tiến trình trên cùng chạy khi còn request đang chờ (đếm số request). Lần đầu vào màn hình hiện khung xương (skeleton) thay cho nội dung. Nút gửi form bị khóa để tránh bấm hai lần |
| Thành công | Vẽ dữ liệu `data` lên màn hình; `message` của server hiện dạng toast màu xanh (VD: "Đặt hàng thành công! Mã đơn hàng: DH261006DZY4.") |
| 422 - dữ liệu không hợp lệ | Hộp lỗi đỏ phía trên form liệt kê từng dòng trong `errors`; người dùng sửa và gửi lại |
| 401 - hết phiên / token sai | Xóa token trong `localStorage`, hiện toast "Phiên đăng nhập đã hết hạn", chuyển tới `#/login?next=<màn hình cũ>` |
| 403 / 404 / 409 / 400 | Hiển thị `message` của server: trong hộp lỗi khi đang tải màn hình, hoặc toast đỏ khi thao tác nút (VD: hủy đơn đã giao, xóa sản phẩm đã có giao dịch) |
| Mất kết nối / 500 | Thông báo "Không kết nối được máy chủ. Kiểm tra mạng và thử lại." Riêng màn hình chat bỏ qua lỗi tạm thời và thử lại ở lần lấy tin kế tiếp |
| Danh sách rỗng | Hiện trạng thái trống có hướng dẫn (VD: "Giỏ hàng trống." kèm nút "Mua sắm ngay") |
