# 2.5. Thiết kế API dịch vụ

Hệ thống cung cấp REST API cho các ứng dụng client (ứng dụng web SPA `/app`, ứng dụng di động, hệ thống bên thứ ba). API dùng lại toàn bộ tầng Service của hệ thống, nên quy tắc nghiệp vụ (thuốc kê đơn, tồn kho theo lô FEFO, khuyến mãi, phân quyền) giống hệt giao diện web. Mã nguồn nằm trong package `com.hieuthuoc.api`.

## 2.5.1. Quy ước thiết kế API

| Nội dung | Quy ước |
|---|---|
| Base URL | `http://<máy chủ>/api/v1` (có phiên bản `v1` để nâng cấp sau này không ảnh hưởng client cũ) |
| Tài nguyên | Danh từ số nhiều, chữ thường, nối bằng gạch ngang: `/products`, `/orders/{code}`, `/me/addresses/{id}`. Tài nguyên của người đang đăng nhập đặt dưới `/me`; nghiệp vụ nhân viên dưới `/staff`, quản trị dưới `/admin`. Hành động nghiệp vụ không thuộc CRUD dùng động từ con: `/orders/{code}/cancel`, `/prescriptions/{id}/approve` |
| HTTP Method | `GET` đọc dữ liệu; `POST` tạo mới hoặc thực hiện hành động; `PUT` cập nhật toàn bộ; `DELETE` xóa |
| Content-Type | Request: `application/json; charset=UTF-8`. Riêng API có tải tệp (ảnh đơn thuốc, ảnh chat) dùng `multipart/form-data`. Response luôn là `application/json` |
| Đặt tên trường | camelCase: `productId`, `paymentMethod`, `createdAt`. Thời gian theo ISO-8601 (`2026-10-06T13:57:44`), tiền tệ là số nguyên VNĐ |
| Xác thực | Không dùng session/cookie (API phi trạng thái). Client gọi `POST /auth/login` lấy access token (JWT ký HMAC-SHA256, hạn 24 giờ) rồi gửi kèm mọi request: `Authorization: Bearer <token>` |
| Phân quyền | Theo vai trò trong token: công khai (không cần token), `CUSTOMER`, `PHARMACIST`, `ADMIN`; nhân viên được kiểm tra thêm quyền chức năng (`RX_REVIEW`, `ORDER`, `INVENTORY`...) |
| Phân trang | Query `page` (bắt đầu từ 1), `perPage`; thông tin trang trả trong `meta` |
| CORS | Cho phép mọi origin gọi `/api/**` với các header `Authorization`, `Content-Type` |

**Định dạng response thành công:**

```json
{
  "success": true,
  "data": { ... },
  "message": "Thông báo cho người dùng (không bắt buộc)",
  "meta": { "page": 1, "perPage": 12, "total": 26, "lastPage": 3 }
}
```

`data` là đối tượng hoặc mảng; `meta` chỉ có ở danh sách phân trang.

**Định dạng response lỗi:**

```json
{
  "success": false,
  "message": "Dữ liệu không hợp lệ.",
  "errors": ["Vui lòng nhập tên người nhận.", "Số điện thoại người nhận không hợp lệ."]
}
```

`errors` chỉ có khi lỗi kiểm tra dữ liệu (422), liệt kê từng lỗi để client hiển thị trên form.

**HTTP Status Code sử dụng:**

| Mã | Ý nghĩa | Ví dụ |
|---|---|---|
| 200 OK | Thành công | Lấy danh sách, cập nhật, hủy đơn |
| 201 Created | Tạo mới thành công | Đăng ký, đặt hàng, thêm địa chỉ, thêm sản phẩm |
| 400 Bad Request | Yêu cầu sai hoặc vi phạm quy tắc nghiệp vụ | JSON hỏng, chuyển trạng thái đơn không hợp lệ |
| 401 Unauthorized | Chưa đăng nhập, token sai hoặc hết hạn | Gọi `/me` không có token, sai mật khẩu |
| 403 Forbidden | Đã đăng nhập nhưng không đủ quyền / tài khoản bị khóa | Khách gọi `/staff/**` |
| 404 Not Found | Không tìm thấy tài nguyên hoặc endpoint | Sản phẩm đã ngừng bán |
| 405 Method Not Allowed | Sai phương thức HTTP | `DELETE /products` |
| 409 Conflict | Trạng thái hiện tại không cho phép thao tác | Xóa sản phẩm đã có giao dịch, thanh toán đơn đã trả tiền |
| 413 Payload Too Large | Tệp tải lên quá lớn | Ảnh đơn thuốc > giới hạn |
| 415 Unsupported Media Type | Sai Content-Type | Gửi form-urlencoded tới API chỉ nhận JSON |
| 422 Unprocessable Entity | Dữ liệu không hợp lệ | Thiếu trường bắt buộc, sai định dạng số điện thoại |
| 500 Internal Server Error | Lỗi máy chủ | Lỗi không lường trước (được ghi log) |

**Cách client xử lý:** kiểm tra mã HTTP (hoặc `success`).
- Thành công: dùng `data`, hiển thị `message` (nếu có) dạng thông báo ngắn.
- 422: hiển thị danh sách `errors` ngay trên form.
- 401: xóa token, chuyển tới màn hình đăng nhập.
- 403 / 404 / 409 / 400: hiển thị `message`.
- 500 hoặc mất mạng: báo lỗi chung, cho phép thử lại.

## 2.5.3. Đặc tả một số API quan trọng

### a) Đăng nhập - `POST /api/v1/auth/login`

Client dùng khi người dùng đăng nhập; token nhận được dùng cho mọi request cần xác thực.

- **Header:** `Content-Type: application/json`
- **Request body:**

```json
{ "login": "binh@gmail.com", "password": "123456" }
```

| Trường | Kiểu | Bắt buộc | Mô tả |
|---|---|---|---|
| login | string | Có | Email hoặc số điện thoại |
| password | string | Có | Mật khẩu |

- **Response 200:**

```json
{
  "success": true,
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiI4Ii...",
    "tokenType": "Bearer",
    "expiresIn": 86400,
    "user": { "id": 8, "fullName": "Lê Thị Bình", "email": "binh@gmail.com", "phone": "0987654321",
              "role": "CUSTOMER", "points": 936, "permissions": [] }
  },
  "message": "Đăng nhập thành công."
}
```

- **Lỗi:**
  - 422 khi thiếu trường (`errors`: "Vui lòng nhập Email / số điện thoại.", "Vui lòng nhập Mật khẩu.");
  - 401 khi sai thông tin ("Email/số điện thoại hoặc mật khẩu không đúng.");
  - 403 khi tài khoản bị khóa.

### b) Tìm kiếm sản phẩm - `GET /api/v1/products`

Màn hình danh sách sản phẩm dùng để tìm kiếm, lọc theo danh mục, loại thuốc, khoảng giá và sắp xếp.

| Query | Kiểu | Mô tả |
|---|---|---|
| q | string | Từ khóa: tên thuốc, hoạt chất (tìm được cả khi gõ không dấu) |
| category | string | Slug danh mục (gồm cả danh mục con) |
| type | string | `OTC`, `ETC`, `SUPPLEMENT`, `DEVICE`, `COSMETIC` |
| min, max | number | Khoảng giá |
| inStock | boolean | Chỉ sản phẩm còn hàng |
| sort | string | `bestseller` (mặc định), `price_asc`, `price_desc`, `newest`, `name`, `rating` |
| page, perPage | number | Trang (mặc định 1), số dòng / trang (mặc định 12, tối đa 50) |

- **Response 200:**

```json
{
  "success": true,
  "data": [
    { "id": 4, "name": "Ibuprofen 400mg", "slug": "ibuprofen-400mg", "image": null,
      "drugType": { "code": "OTC", "label": "Thuốc không kê đơn" }, "prescription": false,
      "category": "Giảm đau, hạ sốt", "activeIngredient": "Ibuprofen", "strength": "400mg",
      "unit": "Vỉ", "price": 7000, "oldPrice": null, "flashPrice": null, "available": 120,
      "rating": 4.5, "reviewCount": 2 }
  ],
  "meta": { "page": 1, "perPage": 12, "total": 26, "lastPage": 3 }
}
```

- **Lỗi:** 404 khi `category` không tồn tại.

### c) Báo giá giỏ hàng - `POST /api/v1/cart/quote`

API phi trạng thái nên giỏ hàng do client lưu. Mỗi khi khách thay đổi giỏ, client gửi giỏ lên để server tính giá. Server áp dụng đơn vị quy đổi, flash sale / combo / quà tặng, voucher, điểm tích lũy và phí giao hàng, rồi kiểm tra tồn kho.

- **Header:** `Authorization: Bearer <token>`, `Content-Type: application/json`
- **Request body:**

```json
{
  "items": [ { "productId": 4, "unitId": 0, "quantity": 2 }, { "productId": 7, "unitId": 3, "quantity": 1 } ],
  "voucher": "WELCOME10",
  "usePoints": false,
  "shippingMethod": "DELIVERY",
  "province": "Hà Nội"
}
```

`unitId = 0` là đơn vị gốc; các đơn vị quy đổi lấy từ `units` của API chi tiết sản phẩm.

- **Response 200:**

```json
{
  "success": true,
  "data": {
    "lines": [ { "key": "4:0", "productId": 4, "name": "Ibuprofen 400mg", "unit": "Vỉ", "quantity": 2,
                 "unitPrice": 7000, "lineTotal": 14000, "prescription": false, "error": null } ],
    "errors": [],
    "subtotal": 129000, "promoDiscount": 0, "voucher": "WELCOME10", "voucherError": null,
    "discount": 12900, "pointsAvailable": 936, "pointsUsed": 0, "pointsDiscount": 0,
    "shippingFee": 20000, "total": 136100, "prescriptionRequired": false
  }
}
```

- **Lỗi:**
  - 422 khi giỏ rỗng;
  - 401 khi chưa đăng nhập.
- Lỗi theo từng dòng (hết hàng, vượt số lượng tối đa) nằm trong `lines[].error` và `errors`. Voucher không dùng được nằm trong `voucherError` (vẫn trả 200 để client hiển thị).

### d) Đặt hàng - `POST /api/v1/orders`

- **Header:** `Authorization: Bearer <token>`.
- **Content-Type:**
  - `application/json` khi giỏ không có thuốc kê đơn;
  - `multipart/form-data` khi có thuốc kê đơn: cùng các trường (dạng `items[0][productId]`...) kèm tệp `prescription` là ảnh đơn thuốc.
- **Request body (JSON):**

```json
{
  "items": [ { "productId": 4, "unitId": 0, "quantity": 2 } ],
  "voucher": "WELCOME10", "usePoints": false,
  "shippingMethod": "DELIVERY", "paymentMethod": "COD",
  "recipient": "Lê Thị Bình", "phone": "0987654321",
  "province": "Hà Nội", "address": "12 Trần Duy Hưng, Cầu Giấy",
  "note": "Giao giờ hành chính",
  "requestVat": false
}
```

| Trường | Bắt buộc | Mô tả |
|---|---|---|
| items | Có | Danh sách sản phẩm, đơn vị, số lượng |
| shippingMethod | Có | `DELIVERY` (giao tận nơi) hoặc `PICKUP` (nhận tại nhà thuốc) |
| paymentMethod | Có | `COD`, `BANK_TRANSFER`, `PAYOS`, `VNPAY` (theo cấu hình nhà thuốc) |
| recipient, phone | Có | Người nhận, số điện thoại |
| province, address | Khi giao hàng | Tỉnh/thành và địa chỉ chi tiết (có thể thêm `ghnDistrictId`, `ghnWardCode`) |
| voucher, usePoints, note | Không | Mã giảm giá, dùng điểm, ghi chú |
| requestVat, vatCompany, vatTaxCode, vatAddress, vatEmail | Không | Yêu cầu xuất hóa đơn VAT |

- **Response 201:**

```json
{
  "success": true,
  "data": {
    "order": { "id": 93, "code": "DH261006DZY4",
               "status": { "code": "PENDING", "label": "Chờ xác nhận" },
               "paymentMethod": { "code": "COD", "label": "Thanh toán khi nhận hàng (COD)" },
               "paymentStatus": { "code": "UNPAID", "label": "Chưa thanh toán" },
               "subtotal": 129000, "discount": 12900, "shippingFee": 20000, "total": 149000,
               "items": [ ... ], "history": [ ... ] },
    "nextAction": "NONE"
  },
  "message": "Đặt hàng thành công! Mã đơn hàng: DH261006DZY4."
}
```

`nextAction` cho client biết bước tiếp theo:
- `PAY_ONLINE`: gọi `POST /orders/{code}/payment` rồi mở `paymentUrl`.
- `WAIT_PRESCRIPTION_REVIEW`: đơn có thuốc kê đơn, chờ dược sĩ duyệt (trạng thái `PENDING_RX`).
- `NONE`: không cần làm gì thêm.

- **Lỗi:**
  - 422 kèm `errors` khi thiếu thông tin giao hàng, hết hàng, voucher không hợp lệ, hoặc có thuốc kê đơn mà không gửi ảnh;
  - 401 khi chưa đăng nhập;
  - 403 khi tài khoản không phải khách hàng.

### e) Duyệt đơn thuốc - `POST /api/v1/staff/prescriptions/{id}/approve`

Dược sĩ duyệt đơn thuốc khách gửi. Thông tin duyệt được ghi vào sổ bán thuốc kê đơn.

- **Header:** `Authorization: Bearer <token của dược sĩ có quyền RX_REVIEW>`
- **Path parameter:** `id` là mã đơn thuốc.
- **Request body:**

```json
{
  "patientName": "Lê Thị Bình", "doctorName": "BS Trần An", "clinic": "BV Bạch Mai",
  "rxDate": "2026-10-01", "checks": ["valid", "date", "sign", "match"],
  "pharmacistNote": "Uống sau ăn, đủ 7 ngày",
  "qty": { "120": 1 }, "sub": { "121": 15 }
}
```

- `checks`: 4 mục kiểm tra bắt buộc, lấy từ API chi tiết đơn thuốc.
- `qty` / `sub`: điều chỉnh số lượng, thay thuốc cùng hoạt chất theo từng dòng đơn.
- Với đơn "nhờ lên đơn" (khách chỉ gửi ảnh, chưa chọn sản phẩm), gửi `productIds`, `quantities` thay cho `qty` / `sub`.

- **Response 200:** trả về đơn hàng sau duyệt:
  - `PENDING`: tiếp tục xử lý;
  - `AWAITING_CUSTOMER`: dược sĩ có điều chỉnh, chờ khách xác nhận lại.
- **Lỗi:**
  - 400 khi thiếu tên bệnh nhân / bác sĩ, chưa đủ mục kiểm tra, đơn đã hết hiệu lực, hoặc đơn thuốc đã được dùng (cần `reuseConfirmed: true`);
  - 403 khi không có quyền;
  - 404 khi không tìm thấy đơn thuốc.

### f) Cập nhật sản phẩm - `PUT /api/v1/admin/products/{id}`

- **Header:** `Authorization: Bearer <token quản trị>`, `Content-Type: application/json`
- **Request body** (cùng cấu trúc với `POST /admin/products`):

```json
{
  "name": "Panadol Extra", "drugType": "OTC", "categoryId": 2,
  "activeIngredient": "Paracetamol, Caffeine", "strength": "500mg/65mg",
  "unit": "Vỉ", "price": 15000, "oldPrice": null,
  "units": [ { "name": "Hộp", "factor": 15, "price": 210000 } ],
  "minStock": 10, "active": true, "equivalentIds": [5, 9]
}
```

- **Response 200:** sản phẩm sau cập nhật (thông tin, đơn vị quy đổi, thuốc tương đương).
- **Lỗi:**
  - 422 khi tên < 2 ký tự, giá ≤ 0, thiếu đơn vị, hoặc giảm giá cho thuốc kê đơn;
  - 400 khi đơn vị quy đổi không hợp lệ;
  - 404 khi không tìm thấy sản phẩm.
- `DELETE /admin/products/{id}` trả 409 nếu sản phẩm đã có lô kho, phiếu nhập hoặc đơn hàng. Khi đó client nên chuyển sang "ngừng bán" (gửi `active: false`).
